# Security Policy

This repository is maintained with security in mind. We take vulnerability reports seriously and appreciate responsible disclosure from the community.

## Reporting a vulnerability

If you discover a security issue in this project, please do not open a public issue or pull request that discloses the vulnerability.

Instead, report it privately by emailing the maintainer at:

- rohit.tiwari.leo@example.com

Please include:

- a clear description of the vulnerability
- affected files, versions, or components
- steps to reproduce the issue
- the potential impact
- any suggested remediation or mitigation

We ask that you allow us a reasonable amount of time to investigate and fix the issue before publicly disclosing it.

## Supported versions

The project currently supports the latest version on the default branch. Security fixes are generally provided for the most recent release line unless otherwise noted.

## Response expectations

We will make every effort to:

- acknowledge receipt of the report within 5 business days
- assess the issue and determine severity
- provide a status update during investigation
- coordinate a fix and responsible disclosure timeline

## Security best practices

When contributing to this repository:

- do not commit secrets, tokens, or credentials
- validate inputs and handle errors securely
- avoid introducing vulnerable dependencies or unsafe patterns
- keep dependencies up to date and review security advisories
- use least-privilege permissions for automation and deployment workflows

## Disclosure policy

We prefer coordinated disclosure. If a vulnerability is confirmed, we will work to fix it and may publish a security advisory after the remediation is available.

Thank you for helping keep this project and its users safe.
